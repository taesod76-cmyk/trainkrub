# คู่มือระบบสำรองข้อมูลอัตโนมัติ (เทรนคับ / TRAINKUB)

## มันทำอะไรให้เอง
ทุกคืนเวลา 03:40 น. (เวลาไทย) ระบบจะ
1. อ่านข้อมูลทั้งหมดของแอป (ลูกค้า เทรนเนอร์ การจอง แพ็กเกจ รหัสผ่านแบบเข้ารหัส) ด้วยบัญชี "อ่านอย่างเดียว" ที่ลบหรือแก้ข้อมูลไม่ได้เลย
2. เทียบกับเมื่อคืน ถ้าข้อมูลหายผิดปกติ (เช่น การจองหายหมด หรือลูกค้าหายเกิน 10%) จะ **ส่งอีเมลเตือนจาก GitHub ถึงคุณ** และเตือนซ้ำทุกคืนจนกว่าคุณจะตรวจเอง
3. ล็อกไฟล์สำรองด้วยกุญแจสาธารณะ เปิดได้ด้วยกุญแจส่วนตัวที่อยู่ในคอมคุณเท่านั้น เก็บไว้ 90 วันที่ GitHub > Actions
4. เช็กด้วยว่าเว็บและฐานข้อมูลยังตอบอยู่ ถ้าไม่ตอบก็ส่งอีเมลเตือน

ระบบ **เตือนเองอัตโนมัติ แต่ไม่กู้เองอัตโนมัติ** เพราะถ้ากู้เองตอนที่ข้อมูลล่าสุดยังดีอยู่ อาจเขียนทับของใหม่ได้ คุณเป็นคนยืนยันก่อนเสมอ

## สิ่งที่ต้องรักษาให้ดี
- ไฟล์ `D:\TRAINKUB_BACKUP_KEY\backup_private.pem` คือกุญแจส่วนตัว **ห้ามส่งใคร ห้ามอัปโหลด ห้ามใส่ใน GitHub** (รวมถึงห้ามส่งให้ Claude)
- **ก๊อปกุญแจนี้ไปเก็บอีกที่หนึ่ง** (แฟลชไดรฟ์) ถ้ากุญแจหาย ไฟล์สำรองทุกไฟล์จะเปิดไม่ได้ตลอดไป และไม่มีใครสร้างใหม่แทนได้
- ไฟล์สำรองเก็บ 90 วัน ควรโหลดมาเก็บไว้เองเดือนละ 1 ไฟล์ที่ `D:\TRAINKUB_BACKUPS\`
- เดือนละครั้งเข้าดูหน้า Actions ว่ามีเครื่องหมายถูกสีเขียวของเมื่อคืน

## ถ้าได้อีเมล "DATA LOOKS MISSING"
1. เปิด GitHub > Actions > รันที่เป็นสีแดง จะเห็นข้อความว่ากลุ่มข้อมูลไหนหาย (เช่น `every "booking" row is gone`)
2. เปิดแอปดูว่าหายจริงไหม
3. ถ้าหายจริง ให้กู้ (ดูด้านล่าง) หรือเปิดแชตกับ Claude แล้วบอกว่า "ข้อมูลหาย อยากกู้" จะพาทำทีละขั้น
4. ถ้าที่ลดลงคือสิ่งที่คุณตั้งใจ (เช่น ลบข้อมูลทดลอง) ให้กด Run workflow แล้วติ๊ก **accept** หนึ่งครั้ง ระบบจะยอมรับตัวเลขใหม่

## ถ้าได้อีเมล "BACKUP FAILED"
เปิดหน้ารันดู บรรทัด "What the backup said" บอกสาเหตุ และ "Password check" บอกความยาวรหัส (ต้อง 64 ตัว) สาเหตุที่เจอบ่อย: รหัสผ่านที่เก็บไว้เก่าหรือคัดลอกมาไม่ครบ (รัน 09 ใหม่ แล้วคลิกขวาที่ช่องรหัสเลือก Copy cell แล้วแก้ Secret), โปรเจกต์ Supabase ถูกพัก (เข้า Supabase กดเปิดใหม่), หรือใส่ host ผิดชนิด (ต้องเป็น Session pooler)

**หลังเปลี่ยนรหัส ตัวกลางเชื่อมต่อของ Supabase อาจจำรหัสเก่าไว้ไม่กี่นาที** ถ้าความยาวรหัสเป็น 64 แต่ยังขึ้น `password authentication failed` ให้ไม่ต้องเปลี่ยนอะไรเพิ่ม รอ 5 นาทีแล้วกด Run workflow ใหม่ การเปลี่ยนรหัสซ้ำจะทำให้ต้องรอใหม่

## วิธีกู้ข้อมูล
1. GitHub > Actions > รันสีเขียวที่ต้องการ > Artifacts > ดาวน์โหลด `backup-...` แตก zip ได้ไฟล์ `.cms` ไปวางที่ `D:\TRAINKUB_BACKUPS\`
2. รันสคริปต์ `backup\restore_backup.ps1` (Claude รันให้ได้) มันจะสร้างไฟล์ `RESTORE_01.sql` ... ในโฟลเดอร์ `D:\TRAINKUB_RESTORE\...` (ยังไม่แตะฐานข้อมูล)
3. เอาไฟล์ทีละไฟล์ตามลำดับไปวางใน Supabase > SQL Editor แล้วกด Run

โหมดกู้:
- `missing` (ค่าเริ่มต้น): ใส่คืนเฉพาะแถวที่หาย ของที่ยังอยู่ไม่ถูกแตะ ปลอดภัยที่สุด
- `overwrite`: ใส่คืนและเอาค่าในไฟล์สำรองทับแถวที่ยังอยู่ (ใช้ย้อนการแก้ผิด)
- `replace`: ล้างตารางก่อนแล้วใส่ทั้งหมด (ใช้กับฐานข้อมูลใหม่เท่านั้น)

## ทดสอบเตือนว่าอีเมลมาถึง
GitHub > Actions > "Nightly backup and check" > Run workflow > ติ๊ก **simulate_alarm** > Run ต้องขึ้นสีแดงและมีอีเมลเข้า (ถ้าไม่มี ให้เช็ก GitHub > Settings > Notifications > Actions ว่าเปิดอีเมลสำหรับ workflow ที่ล้มเหลว)
